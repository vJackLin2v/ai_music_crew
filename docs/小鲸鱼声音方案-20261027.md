# 小鲸鱼声音方案 v1（2026-10-27）

## 0. 一句话

音色已定：**A 清甜少女（edge-tts zh-CN-XiaoyiNeural）**。
要同时满足「让她唱 Suno 的歌」和「上架汽水音乐做成专辑」，需要**两条产线**，因为这两件事的产物不是同一个东西。

## 1. 必须先澄清的一件事

| 需求 | 海绵音乐能做吗 | 说明 |
|---|---|---|
| 让「小鲸鱼」唱一首歌 | ✅ 能 | 克隆音色 → 用克隆音色演唱**海绵内生成的歌** |
| 把**已生成的 Suno 歌**换成她的声音 | ❌ 不能 | 海绵不接管外部音频；它只对平台内生成的曲目换声 |

所以：
- **要 Suno 的曲** → 必须走本地 SVC（分离 + 换声 + 混音）
- **要快、要能一键发汽水** → 走海绵，但曲目由海绵生成

两条线可以并行，产出不同，别混在一起验收。

## 3. 路线甲：海绵音乐生产线（平台原生，最快能上架）

### 3.1 前置（你本人操作，我做不了）
1. 抖音号登录海绵音乐（haimian.com）
2. 实名认证（汽水发歌必须有）
3. 音色克隆：上传 `voice/xiaojingyu/reference-long.mp3`
4. 拿到「音色特征」后，确认它能在**演唱**场景使用（不只是说话）

### 3.2 生产链路
```
crewAI 出 brief / 歌词 / 编曲 → 转成海绵的对话式提示
  → 生成 3-5 版 → 挑一版 → 用克隆音色演唱
  → 导出 → （可选）本地混音母带 → 发汽水
```

### 3.3 提示词迁移要点
现有 [suno_prompt.txt] 是「Style Prompt + 分段歌词」格式，迁到海绵需要改成**自然语言对话**：

- Suno 写法：`中国古风/国风流行, 65-78 BPM, D羽调式, 女声主唱（空灵略带气声）...`
- 海绵写法：「写一首古风抒情歌，节奏慢一点，六十几到七十几 BPM，要用五声音阶那种味道，女声，唱得轻、带点气声，情绪是遗憾和回忆。歌词写一段将军和红颜的生离死别。」

### 3.4 这条线的真实限制
- 风格控制精度不如 Suno 提示词（你现有 crewAI 的分层产出会被压缩成一段话）
- 歌词未必逐字唱对（中文时长/咬字问题普遍）
- 编曲质量天花板取决于平台，无法介入分轨
- **不能接管你已有的 37 个作品**

## 4. 路线乙：本地 SVC 生产线（要 Suno 的曲就走这条）

### 4.1 环境（这台机器）
| 项 | 现状 | 处理 |
|---|---|---|
| GPU | RTX 4060 8GB | 够用（RVC 训练 6-7GB 起） |
| Python | 系统 3.14，装不了 torch | uv 建 3.11/3.12 隔离环境 |
| ffmpeg/ffprobe | **缺失** | 必装 |
| 磁盘 | C: 只剩 15.2GB | **所有模型/环境放 H:**（659GB 空闲） |
| 内存 | 15.9GB | 分离时别开别的重活 |

### 4.2 脚本设计：`make_cover.py`（独立，跑通后再接进 ai_music_crew）

```
输入：song.mp3 + 音色模型（rvc.pth/index 或 seed-vc 参考音）
  ↓ [1] separate    htdemucs_ft（默认）/ BS-RoFormer（离线高质量）
  ↓ [2] split-lead  vocals 里再分主唱/和声（否则和声会被换成同一音色，一听就假）
  ↓ [3] convert     Seed-VC 零样本（先跑通）→ RVC（发布级）
  ↓ [4] mix         电平对齐 + 高通 80Hz + 去齿音 + 混响匹配（关键）
  ↓ [5] master      pyloudnorm → -14 LUFS，真峰值 ≤ -1 dBTP
  ↓ [6] report      LUFS / 时长 / 换声前后对比片段
输出：out/<song>/cover.wav (44.1k/24bit) + cover.mp3 (320k) + report.json
```

关键设计：
- 每步产物落盘、可单独重跑（换声参数要反复调，不能每次从头分离）
- `--from convert` 这类断点参数
- 所有随机性固定 seed，保证 A/B 对比时只有变量在变

### 4.3 质量门（发布级的最低标准）
1. 盲听：随便截 20 秒，能听出「是同一个人在唱」，不是「AI 换皮」
2. 齿音：s/sh/x 不刺、不糊
3. 混响：人声要落在伴奏同一个空间里，不能干贴
4. 响度：-14 LUFS ±1，真峰值不爆
5. 高音：连续高音不破、不电音（不行就换曲，别硬修）

### 4.4 曲目策略
她在**慢歌抒情**上效果最好（国风正好是强项）；快歌、连续高音、强颤音是短板，选曲时主动避开。

## 4.5 批量模式（2026-10-27 新增）

```bash
# 一次处理一个目录里的所有歌，单首失败不影响后面的
python make_cover.py batch --in work/batch-in --out out/batch --steps 30 --reverb 0.12

# 只跑前 2 首
python make_cover.py batch --in work/batch-in --out out/batch --limit 2
```

- 跳过小于 500KB 的文件（试听片段）
- 每首一个独立 work 目录：`work/batch/<歌名>/`，可单独重跑
- 结束时写 `out/batch/batch-report.json`（成功/失败清单）
- 单首耗时参考（RTX 4060）：分离 ~1.5 分钟，换声 ~2.5x 实时（4 分钟歌 ≈ 10 分钟）

## 5. 发行侧（汽水音乐）

- 汽水是抖音系，海绵可直接走平台通道；本地做的成品走**音乐人后台上传**，两条都通
- 上传要：实名、封面、元数据、**AI 声明**（国内还有生成式 AI 内容标识要求）
- 已实测：免费版 Suno 曲上架没被拦 —— 但平台对 AI 内容的分成/投诉处理是后置的，出问题在账号层面
- 汽水有 **AI 音乐专属分成池**，AI 作品播放分成比普通作品高约 15%

## 5.5 环境状态（2026-10-27 已完成 P1-P3 首轮）

| 项 | 结果 |
|---|---|
| ffmpeg | `H:\tools\ffmpeg\ffmpeg-master-latest-win64-gpl\bin\ffmpeg.exe` |
| Python 环境 | `H:\ai_music_crew\.svc`（3.11.15，torch 2.4.0+cu124，CUDA 可用） |

| 母带 | 实测输出 -14.00 LUFS / 峰值 -1.38 dBFS |

踩过的坑（已修）：
1. `uv` 装包时改写 Windows PE 资源失败 → 改用 `python -m pip` 并把 TEMP 指到项目内。
2. 系统 `HTTP_PROXY` 指向 DSH 内部端口，huggingface_hub 连不上 → `make_cover.py` 统一走 Clash 7890。
3. `pedalboard.Limiter` 带自动补增益，会把 -14 LUFS 抬到 -10 LUFS 并削顶 → 换成自己实现的 `peak_limit()`。
4. `torch` 必须锁 2.4.0：2.6+ 的 `torch.load` 默认 `weights_only=True` 会让 Seed-VC 读 checkpoint 失败。

## 5.55 音色微调（Seed-VC fine-tune，2026-10-27）

零样本是"借音色"，微调才是"学音色"。官方支持极少数据（最少 1 条）快速微调。

### 数据与训练
```bash
# 语料：voice/xiaojingyu/train/  335 段（约 15 分钟）：项目歌词 + 90 句日常口语 × 3 种语速
cd tools/seed-vc
python train.py \
  --config configs/presets/config_dit_mel_seed_uvit_whisper_base_f0_44k.yml \
  --pretrained-ckpt checkpoints/models--Plachta--Seed-VC/snapshots/<hash>/DiT_seed_v2_uvit_whisper_base_f0_44k_bigvgan_pruned_ft_ema_v2.pth \
  --dataset-dir H:\ai_music_crew\voice\xiaojingyu\train \
  --run-name xiaojingyu --batch-size 1 --max-steps 1200 --save-every 300 --num-workers 0
```
- 4060 8GB：1200 步约 10 分钟，显存够用（batch-size 1）
- 产物：`runs/xiaojingyu/ft_model.pth`（749MB）+ 同目录 config
- 中间 checkpoint 每个 2.1GB，训练完记得删

### 用微调模型推理
```bash
python make_cover.py convert --work <work> --ref voice/xiaojingyu/reference-long.mp3 \
  --steps 30 --svc-dir svc_ft \
  --ckpt tools/seed-vc/runs/xiaojingyu/ft_model.pth \
  --cfg  tools/seed-vc/runs/xiaojingyu/config_dit_mel_seed_uvit_whisper_base_f0_44k.yml
```
`--svc-dir` 让微调版和零样本版并存，方便 A/B。

### 气息补偿：已关闭（实测失败）
试过从 demucs 的 vocal 干声里把"气口"搬回换声结果（气口占 4.7%），
但干声的静音段里混着伴奏残留和分离算法的高频噪声，**-13dB 和 -20dB 两档都有明显嘶声**。
结论：素材不干净，此路不通；要做只能另外合成干净呼吸，暂缓。
`--breath` 默认 0（关闭）。

## 5.6 海绵音乐实测记录（2026-10-27，重要）

### 入口（实测路径）
```
创作 → 自定义写歌 → [ + 选音色 ] → [ 新增音色 ] → 开始清唱 → 计时器点停 → 提交
```
- 必须先登录（弹「登录后即可选择 AI 音色」）
- **不支持上传文件**：页面里 `input[type=file]` 为 0，只有麦克风录制
- 录制上限 60 秒，界面给一份逐字稿（茉莉花 / 月亮代表我的心 / 甜蜜蜜 / 送别 / 一段朗读）
- 提交后服务端「音色制作中 x%」，约 20~40 秒出结果

### 校验门禁
```json
{"status": 3, "payload": "{\"err_code\":30000408,\"err_message\":\"错字较多，请对照文本重试\"}"}
```
服务端会对录音做**识别并与界面文本逐字比对**。四次提交全部被拒：

| 素材 | 时长 | 结果 |
|---|---|---|
| 指定朗读段（逐字对应） | 24s | ❌ 30000408 |
| 全剧本（四首歌+朗读，+35% 语速） | 58s | ❌ 30000408 |
| 纯茉莉花（自然语速） | 24s | ❌ 30000408 |
| 混合内容 | 40s | ❌ 30000408 |

结论：它验的是「**是不是真的在唱**」，字面对不对不是判定依据。合成人声过不去。
被拒的音色不会留在账户里，也不扣积分。

### 让音频真正进麦克风（已验证可用）
| 环节 | 做法 | 实测 |
|---|---|---|
| Chromium 假麦克风 | `--use-file-for-fake-audio-capture` | ❌ **输出纯静音**（peak=0, rms=0） |
| 虚拟声卡 | 装 VB-CABLE → 播放到 `CABLE Input`，录音用 `CABLE Output` | ✅ loopback peak 0.50 / rms 0.084 |
| 浏览器选设备 | init script 劫持 `getUserMedia` 强制 `deviceId` | ✅ 采样 peak 0.98 |
| Python 播声 | `sounddevice`，设备索引：CABLE Output=12，CABLE Input=16 | ✅ |
| 上传确认 | 抓包看到 2.6MB 音频传到 `tos-d-x-hl.snssdk.com` | ✅ 链路通 |

### 因此的路线选择
克隆门禁需要"真人在唱"，与我们用合成音色的目标冲突。**主路线改为本地 SVC（C 线）**：
平台那套只保留「用它生成伴奏 → 本地换声 → 汽水后台上传」的用法，不再依赖它的音色克隆。
